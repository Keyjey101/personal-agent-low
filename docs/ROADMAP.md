# Анализ и дорожная карта «Диспетчера»

Дата: 2026-10-01. Основа: реальный лог использования 29.09–01.10, полный код-аудит,
исследование референсов (OpenAI dots, Generative Agents, Tiny Habits, GTD, батчинг
уведомлений). Документ — рабочий: приоритеты пересматриваются по мере данных.

## 1. Что сказал реальный лог (34 часа, 8 сообщений пользователя)

| Факт | Вывод-гипотеза |
|---|---|
| Отказ от кухни в 23:15 + «отложи до выходных» | Мыслит окнами (выходные), а не задачами. Планирует вечером, в момент усталости |
| 23:18 — приносит РЕШЕНИЕ с причиной («оригинал дорог → поликарбонат») | Ночью — стратег, днём — исполнитель. Причины решений — золото для памяти |
| 23:20 — «пойду гулять с собакой и замеряю ЗАОДНО» | Сам делает habit stacking. Система должна поддерживать якоря-рутины, а не только время |
| 7:01 и 13:02 сам пишет в «запрещённые» часы | Реальные микро-окна: утренняя дорога ~7:00, обед ~13:00. Запрет 7–18 слишком грубый — асимметрия: сам писать можно, его дёргать нельзя |
| 21:54 — пять раз подряд жмёт «Другое» | Искал что-то и не нашёл. 6 предложений за день — 0 принятых. Скоринг «правильный», но не попадает в настроение момента |
| За 34 часа: 0 выполненных задач | Главная метрика (выполнено/день) на нуле. Система пока «проситель», не «исполнительный контур» |
| 3 фактические ошибки бота («10 дней» ×2, «подрядчик», «спать» в 7 утра) | Доверие хрупкое: одна дичь стоит недели недоверия. «Никогда не врать» — приоритет №1 |

**Ключевой инсайт:** пользователь приносит стратегии ночью, исполняет — в случайные
микро-окна. Система должна разделять эти режимы: «думать со мной» (вечер/ночь) и
«дать одно действие на 2–10 минут» (микро-окна). Порог входа сейчас завышен:
все предложения — «начать» (10–30 мин с подготовкой), а не «сделать» (2–5 мин без подготовки).

## 2. Итоги код-аудита (полный отчёт — в истории коммитов/реплике агента)

Критическое (чинится немедленно, до всего продуктового):
1. **Дедлок WriteLock** — первая ночная рефлексия с write-операцией навсегда вешает
   планировщик: умирают напоминания, проактивность, бэкапы, истечение сессий;
   текущая задача сессии навсегда остаётся `active` и исчезает из кандидатов.
2. **`\b` после кириллицы не работает** — «готово»/«стоп»/«другое» в режиме «веди меня»
   не распознаются, текст уходит в LLM, который может закрыть не ту задачу.
3. **Fire-and-forget промисы без catch** — любой сбой Telegram API или гонка кнопка+текст
   роняют процесс (unhandled rejection).
4. **Неэкранированный HTML** — задача с `<` в названии ломает отправку сообщений.
5. **Бомба расходов**: превышение дневного лимита GLM не останавливает рефлектор —
   он ретраится каждые 30 секунд, каждый раз реально платя за API-вызов.
6. **Утечка сессий**: повторный `/lead` оставляет прошлую текущую задачу в `active` навсегда.

Плюс ~20 major/minor: «Не буду» мутит не ту тему, «Другое» пинг-понгит A↔B,
`drop_pending_updates` глотает сообщения при простое, нет мобильной вёрстки, ошибки
API возвращаются с 200 и молча глотаются фронтом, рефлектор теряет события за
пределами cap и не ограничивает промпт, и др.

## 3. Референсы: что переносим (исследование dots + научная база)

«Крутизна» dots — не магия модели, а три переносимых принципа: (1) работа продолжается
без тебя и возвращается готовой к одному клику; (2) read-only по умолчанию, необратимое —
только с одобрения; (3) видимый отчёт вместо молчаливого фона.

Научная база даёт конкретику:
- **Generative Agents (Stanford)**: скоринг памяти по свежесть×важность×релевантность;
  рефлексия производит выводы второго порядка, а не архив.
- **Батчинг уведомлений (Duke)**: 2–3 дайджест-окна в день лучше и потока, и полной
  тишины; молчание 2+ подряд — сигнал «не в тот момент».
- **Tiny Habits / habit stacking (Fogg, Gollwitzer, d=0.65)**: якорь «после [рутины] я
  [действие]» + дословная репетиция связки при создании.
- **GTD**: next physical action обязателен у каждого проекта; weekly review — воскресная
  короткая сверка «у каждого проекта есть шаг».
- Анти-паттерны конкурентов (Motion/Reclaim): обслуживание системы не должно стать
  отдельной работой; никакого автоперепланирования-фетиша; «Диспетчер» — инструмент,
  не друг (без овер-антропоморфизма).

## 4. Дорожная карта

### P0 — стабилизация (делается сейчас, без обсуждения — это починка сломанного)
- [x] Реентерабельный WriteLock (AsyncLocalStorage) + узкая зона лока у планировщика
- [x] Кириллические слова сессии («готово»/«другое»/«стоп») + тесты матчера
- [x] .catch на все fire-and-forget, идемпотентный doneCurrent
- [x] Экранирование HTML во всех исходящих текстах (утилита + прогон по источникам)
- [x] Превращение лимита GLM из «бомбы» в предохранитель: проверка ДО вызова,
      пометка дня при лимите, cooldown 30 мин при сетевых сбоях рефлектора
- [x] Утечка сессий: возврат current-задачи в todo при повторном /lead
- [x] Рефлектор: last_reflection_at = ts старейшего обработанного события; кап промпта
- [x] flushQueue: очередь не чистится до успешной отправки; ошибки ловятся
- [x] drop_pending_updates=false; валидация limit в /api/events; ошибки API — 4xx
- [x] Мобильная вёрстка (минимальный media-query)

### P1 — продукт «под твоё поведение» (после обсуждения, ~1–2 итерации)
1. **Режимы дня / микро-окна.** Вместо жёсткого «7–18 не беспокоить»: утреннее окно
   «дорога» (5–10 мин дела), обеденное (по твоему ответу), вечерний ритуал
   «что успел → одно действие → молодец». Между окнами — тишина (батчинг, Duke).
2. **Микродействия 2–5 мин + «разогретое» действие (из dots):** к утреннему окну бот
   готовит контекст действия (чек-лист шагов, прошлые замеры из графа) — «X готов к
   старту», а не «сделай X».
3. **Якоря-рутины:** поле «якорь» у задачи («после выгула собаки»), репетиция связки
   при создании (Gollwitzer), напоминание в момент рутины, а не по часам.
4. **Вечерний режим стратега:** ночью бот не пихает действия, а помогает думать:
   фиксирует решения и причины в граф, раскладывает на шаги на завтра.
5. **Разбор отказов:** серия «Другое»/игноров по категории (тип задачи × время) →
   рефлектор ночью понижает вес этой категории (личные коэффициенты поверх скоринга).

### P2 — «умный» (когда P1 приживётся)
- Скоринг памяти/кандидатов по recency×importance×relevance (Generative Agents).
- Недельный обзор по GTD: воскресенье, 3 блока, 10 минут.
- Калибровка оценок времени по факту (started_at/completed_at уже пишутся).
- Утренний дайджест с 3 инсайтами рефлексии «на подтверждение».
- Undo в вебе и статистика принятия предложений (accepted/suggested по категориям).

### Метрики успеха (добавить в /status и веб)
- выполнено задач/день (главная; сейчас 0) и доля дней с ≥1 завершением;
- accepted/suggested по категориям и времени суток;
- фактическое vs оценённое время;
- «ошибок доверия» (выдуманные факты) — цель 0.

## 5. Вопросы к тебе (ответы меняют дизайн P1)

1. **Таймзона:** ты в UTC+5 (судя по логу)? Скажи точную (например Asia/Yekaterinburg) —
   иначе тихие/рабочие часы сдвинуты на 2 часа.
2. **Микро-окна:** можно ли писать утром ~7:00 (одно короткое) и в обед ~13:00? Или
   строго после 18:00, как сейчас?
3. **Вечерний ритуал:** хочешь короткое «закрытие дня» (~21:30–23:00): что успел,
   одно действие или «спокойной ночи» без дел?
4. **Якоря:** какие повторяющиеся рутины привязывать? (выгул собаки, утренний кофе,
   дорога на работу…) — перечисли 2–3.
5. **Общение:** бот сейчас только «деловой». Нужен ли режим «просто поговорить о делах
   и планах» без предложений действий, или держим строгость?
6. **Обслуживание:** готов тратить ~5 мин/нед на воскресный обзор с ботом (GTD-style)?
